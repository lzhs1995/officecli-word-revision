# 全文统稿：人大格式对标、Word 实现与验收

适用于已经完成内容修订、准备合并或排版的论文。先冻结输入，在副本上工作。原始章节是内容依据，确认过的学校规范和本次用户要求是格式依据；既有成稿是经验来源，不能自动升级成学校规定。

本说明依据用户提供、保存于 **2026-03-07** 的《中国人民大学研究生（硕士、博士）学位论文排版要求》快照。未证明它是学校最新官网版本。“2026 profile”是本工具的基线名称。逐条来源、性质和检查范围见 [规则来源矩阵](ruc-rule-sources.json)；可运行契约见 [整稿结构检查](thesis-integrity.md)。

## 1. 先分清规则性质

| 层次 | 本任务例子 | 执行方式 |
|---|---|---|
| 学校存档明确数值/方式 | A4、45/40/35/30 mm、20 pt、图表章号、图片嵌入型 | 将原文、单位、版本和 profile 属性逐项对应 |
| 学校存档推荐 | 三线表、使用样式 | 默认建议；特殊承载表须保留用途 |
| 本用户明确要求 | 全文末汇总书目，英文在前、中文按完整拼音；表内汉字/混合左、其他右 | 写入项目契约，不冠以普遍校规 |
| 工程建议 | 显式锚点、两次分页结果一致、输出成员校验 | 解释它解决的失败，不冒称学术或学校要求 |
| 未确定事项 | 罗马数字大小写、是否每块独立分节、存档占行与段距解释 | 保留依据与分歧；只提示，不通过猜测批量改稿 |

规范变更要增加 `profile_version` 并记录差异。历史任务保留自己的 profile 哈希；升级不自动重跑、重新冻结旧论文。GB/T 7714 的版本和引用制度按学校及本任务确认值执行，不能因看到另一个年份便悄悄更换。

## 2. 把排版要求映射到可核对象

| 对象 | 当前存档数值 | 实现与核验 |
|---|---|---|
| 内页 | A4；上45、下40、内35、外30 mm | 检查每一节的 `pgSz/pgMar`，保留横向节；双面用对称页边距 |
| 页眉 | 居中论文题目，宋体10.5 pt，距边2.5 cm | 清除继承缩进；核默认/偶数/首页三类页眉及最终 PDF 实际位置 |
| 页脚 | 博士页码外侧；Times New Roman 10.5 pt，距边2.5 cm | 奇页右、偶页左；核真正 PAGE 域及印刷页码，不能只看物理页序 |
| 正文 | 宋体/Times New Roman 12 pt，两端、首行2字、固定20 pt、前后0 | 使用样式及明确单位；字符缩进与长度缩进一起核 |
| 标题 | 章18 pt黑体；一级14 pt黑体；二级12 pt黑体；三级按存档为12 pt宋体 | 按语义样式设置大纲级别；不把普通加粗段误认为标题 |
| 目录 | 目录标题16 pt黑体居中；一级14 pt黑体；二三级12 pt宋体 | 分开配置 TOC 标题与 TOC 1/2/3；页码制表位与引导符单独核 |
| 图表文字/题注 | 宋体10.5 pt、取消首行缩进；章号格式“图/表 1-1” | 显式对象绑定、SEQ、书签和 REF；表格内容可编辑 |
| 脚注 | 原生上标、页底、每页编号、小五宋体9 pt | 同时核 settings 和每节覆盖；正文脚注引用必须对应真实 footnotes 部件 |
| 书目/致谢/附录 | 标题黑体12 pt、内容宋体12 pt | 另设文后标题样式，不能无条件套18 pt章标题；是否入目录由确认的目录层级决定 |

存档的“占行”和段前/段后不是一组可以未经解释就同时硬编码为总高度的数值。遇到冲突，保留原文并对照确认模板；工程验收不能偷偷选择一种解释后声称全部校规已满足。

一次统稿为改善外观，把原来缺字号/对齐的参考文献标题修成了18 pt居中章标题。该处置有原生和视觉回执，但与本存档“文后标题12 pt黑体”不同，不能从历史PASS推导为学校要求。新版提供独立 `backmatter_title`；对历史冻结稿只记录差异，未来任务按确认来源配置，不能为了统一外观自动套用章标题。

字体检查有两层：OOXML 的直接格式、样式和主题；以及 PDF 中实际渲染字形。主题中的 `minorEastAsia` 可能依 `themeFontLang` 转向其他东亚字体。设置字体名称时处理冲突的 theme 属性；只有明确中文模板要求时才修改东亚主题语言，不能全局替换外文内容字体。

“全部缩进清零”只适用于确实需要零缩进的目标，如页眉或指定表格。正文两字首行与书目悬挂缩进有不同语义：非零首行要处理竞争的 `hanging/hangingChars`，悬挂与目录层级则要使 `left/start` 及字符别名一致。把长度设为24pt却留下字符0，或给非零首行附加悬挂0，都可能使Word采用与预期不同的结果。修复后核保存重开和实际PDF，不能只逐属性看“数字写进去了”。

## 3. 分节决策：先看页面属性是否变化

“另起一页”“成为独立内容块”“拥有不同页眉”“页码重新从1开始”是不同需求。一个分节符也不会自动关闭所有 `LinkToPrevious` 或自动重启页码。

| 场景 | 建议边界 | 页码和页眉处理 |
|---|---|---|
| 中英文摘要、目录、图目录、表目录共用页级设置，只须另起页 | 标题样式 `pageBreakBefore` 或明确分页 | 前置罗马页码连续；无需为了块名一律新节 |
| 上述任一块有独立页眉、首页、页码制度 | 通常“下一页分节符” | 分别配置默认/偶数/首页的页眉和页脚链接 |
| 罗马前置页进入阿拉伯正文 | 新节 | 正文起算1；前置罗马大小写按明确契约 |
| 新章、文末参考文献、附录只须另起页 | 分页即可；已有有用分节可保留 | 连续编号；如用户选择每章分节，按维护策略实施 |
| 新章/文后块还需独立页级设置 | 下一页分节 | 不因新增分节误加 `start=1` |
| 宽表需横向版心 | 横向内容前后建立节边界 | 恢复纵向、页边距、页眉页脚，页码连续 |
| 同页由单栏转多栏 | 条件允许时连续分节 | 注意 Word 对方向、脚注等组合的实际分页行为 |
| 明确要求章从右页/左页开始 | 奇数页/偶数页分节 | 自动装订空页单列；不以删空段消灭它 |
| 封面、声明等不显示页码或页眉 | 按模板使用独立节或首页不同 | “不显示”不等于“不参与编号”，必须分别确认 |

操作顺序：先画出内容块与现有节的映射，再写需要改变的属性，再核每节真实结果。`w:pPr/w:sectPr` 描述在该段落处结束的节；末尾 `w:body/w:sectPr` 描述最后一节。删除分节符可能让前面的文字采用后面节的版式，不能按“空段”批量清理。

页眉与页脚、默认/偶数/首页链接各自独立。同一页眉文本可共享；需要独立编辑时应断开相应链接。`different_first_page_header_footer` 和 `odd_and_even_pages_header_footer` 也须与实际用途一致。检查器能发现链接和重启设置错误，最终奇偶页位置、隐含空页和印刷编号仍由原生 PDF 验收。

## 4. 摘要和三目录

摘要按内容自然排页，不为塞入一页擅自缩字号、改20 pt行距或压页边距。检查中英文标题、摘要正文、关键词的语义样式；避免关键词单独落在只有一行的尾页。摘要、目录等是否显示页眉或占几个编号页，须有来源或用户约定。

正文目录来自正确的大纲级别；图目录和表目录来自对应题注标签。三者都须是原生 TOC 域。手工输入的一页“目录”即使当前页码正确，也不能算可更新目录。典型域分别为 `TOC \o "1-3"`、`TOC \c "图"`、`TOC \c "表"`；实际层级和标签按文档设定。

图表目录也可以按专用题注样式生成，例如 `TOC \t "Figure Caption,4"`。指定目录层级可让图表列表使用独立显示样式，避免与正文TOC 1的字体和缩进互相影响。此时检查器须显式配置 `figure_styles/table_styles`，不能把没有 `\c` 的所有TOC一律认作正文目录；也不能让正文中一句“见图……”共用题注样式而被误收。

只调目录显示文字会在刷新后丢失。要调 TOC 样式、制表位、引导符、缩进和超链接格式；不要全局重设正文样式来修目录。目录自包含、正文提及误收进图表目录、重复题注、丢失附录标题都应逐项核对。

推荐收尾次序：正文及图表布局稳定 → 题注/REF/STYLEREF 等域更新 → 分页 → 三目录及其页码更新 → 再分页。比较连续两次页数及目标页码是否一致，达到本次设置的有界次数还不稳定就保留未决状态。随后保存、关闭、重开，并把三目录目标与最终 PDF 的物理页/印刷页对应。重复次数是稳定性证据，不是“一定正确”的定理。

Word 可能在更新目录时重新生成 `_Toc…` 书签名称。保留两次原始快照，另按实际目标所在 story、显示位置、范围文字、域代码/缓存及内部链接比较。仅名称变化且这些要素一致，可以判为该范围内稳定；同名文字在另一位置仍须失败。不要删除所有书签名后比较，也不要用XML节点序号当显示位置：Word补写运行格式或拆分run就会改变节点序号。可复用 `scripts/word_field_snapshot.py`；它不替代原生执行和目录目标页核验。

## 5. 题注、图表排序与交叉引用

为对象、题注和引用建立稳定 ID。实际对象与题注用书签/显式锚点绑定，显示编号只是可更新结果。图表移动后，重新计算章内序号并刷新 SEQ、REF/PAGEREF、图目录/表目录；不要依靠全局文本替换“表1”这种短字符串。

按章编号可结合章标题编号、`STYLEREF` 和 `SEQ ... \s 1`。仅手打章号加 SEQ 并不自动保证换章后前缀正确；必须核实际域组合与章标题编号体系。分图(a)/(b)属于同一主图时，不应各自增加主图序号。表内模型、估计量和行列次序不因题注排序而改变。

表题通常在表上；表题段落与首行绑定。图题通常在图下；由图片段落的 `keepNext` 绑定图题。不要把所有图题设为 `keepNext`，否则可能连带后面正文形成长链，整串被推到下一页。

检查书签名称/范围、真实 SEQ、引用目标、重复号、缺号和对象的物理顺序。`REF` 的空编号目标常是错误；`PAGEREF` 指向零长度位置书签可以合法。数字连贯不证明论述顺序正确：按首次实质引用和解释逻辑排序，大图表因版心限制延后放置时由作者确认，工具不得自行移动。

## 6. 脚注与文中引用

解释性注释在对应正文位置插入 Word 原生脚注，不使用正文末尾小字、文本框或手工上标冒充。脚注正文落在 `footnotes.xml`，引用 ID 与注释一一对应，引用字体上标；位置和重编号检查文档默认及所有节的 `footnotePr`。省略位置可等效于默认页底，省略编号重启通常不能等效于每页重启。

一次合成原生验证中，只写在文档默认设置里的 `eachPage` 在Word保存后消失，导致三节均回落为连续编号。保留原失败，在后继样例中按schema顺序写入逐节 `footnotePr`，再检查保存结果；不能仅因预保存XML有该值便通过。用同一节的两个不同页面实际脚注检验重编号：一个脚注或两个不同节的脚注不足以区分每页重启和每节重启。该观察不意味着所有Word版本都会丢弃合法文档默认值。

著者—出版年文献引用与解释性脚注可以各司其职；存档允许“顺序编码制”或“著者—出版年制”，不能据“脚注（参考文献及注释）”的标题把所有作者年引文机械改成脚注。需要脚注式文献说明的院系细则应另列来源。注释也可能含文献域，审计须覆盖脚注、尾注、页眉、页脚和文本框，不只扫描正文段落。

复杂域按 begin/separate/end 边界逐个解析，兼容拆开的 instrText、跨段落域、相邻域、嵌套域及 `fldSimple`。不能整段拼接 Zotero JSON：一段可能有两个独立引文。域锁定、`dontUpdate`、域内重复 URI 和破损 JSON 应定位到具体域；同一文献在不同位置被多次引用是正常现象。

## 7. 全文末唯一书目与英中排序

此项目要求将正文引用的参考文献集中到主稿末尾，英文在前、中文在后。它是明确项目规则；不能写成 RUC 存档规定的通用语言顺序。附录专属文献若只在独立附录中使用，是否保留附录书目按交付范围说明。

统稿前清点各章的活引文、独立条目和局部书目。最终保留一处主稿活 `ZOTERO_BIBL`，并检查没有静态的局部书目残留；域数量为1不能排除正文中还复制着一份普通文本书目。引用次数、独立条目数和书目条数是三个不同量。

按声明的文献语言分组，不能仅凭标题里有汉字就把它归为中文。英文按作者姓名字母顺序，中文按经核实的**完整拼音**比较：同为 C，仍需区分 Cai/Chen/Cheng；同作者再按年份、同年按确认的题名排序键。多音姓、复姓、机构作者、无作者及中英文重复著录要保留人工核实来源。

排序键和显示姓名分离。可在任务专用 CSL 中用语言组和作者排序宏，必要时通过专用 citation-label 辅助中文排序；保留 Extra 中原有字段和原作者名，不能把作者姓名改成拼音只为排得对。采用前检查 CSL 是否实际读取该变量，以及 citation-label 是否影响文中显示。Zotero 元数据写入限于核实过的条目，先备份、按 item version 控制，不把一次项目的批量修复推广为所有库默认操作。

Word+Zotero 原生创建书目及 Refresh 后，保存关闭重开，逐条核真实可见缓存与排序表；再核 PDF 显示、断行和悬挂缩进。只修改 `w:t`、formattedCitation/plainCitation 或 XML 中的 URI，不能冒充 Zotero 已刷新。接口 HTTP 200 和宏受理不证明 Word 已回写。

书目文字、顺序正确也不证明条目段落正确。合成测试曾把两条书目用文本中的换行符连接到一个 `w:t`，本地文本比较通过，Word却把它们排在同一段。样例改用跨段落域，并可通过 `bibliography.entries_separate_paragraphs` 核每条独立段落。真实书目仍由Zotero/CSL生成；不要用手改缓存的方法套用这个测试构造。

## 8. 图表尺寸、美观与独占页

使用当前节的真实版心：可用宽度 = 页宽 − 左右边距 − 需要扣除的装订/栏间空间；可用高度还须扣除标题、题注、注释、段距以及页眉页脚的实际布局影响。横向页重新计算，不沿用纵向的145 mm宽度。

页眉页脚距离不是额外页边距。它们已落在上下页边距内时，不再重复从版心高度扣除；检查实际是否侵入正文区域。多栏时使用当前栏宽，装订线也先核是否已经计入有效内侧边距。

图片等比例缩放，优先保证标签可读。先解决图片容器的单倍行距和嵌入型，再谈缩放；固定20 pt会裁切高图。不能为了留出正文而拉伸图、裁掉置信区间/注释或缩到无法读。容器没有超过版心，也不证明图内文字清楚，仍需按最终尺寸查看。

统计表先稳定字体、两套零缩进、段距，再按内容和列语义分配宽度。已有原生 AutoFit 工具可用于明确选择的表格；不能用代码层面的 autofit 标志冒充 Word 实际适应结果。行高用最小值、保留可增长空间；长表重复正确的表头，超高单行与“禁止跨页断行”冲突时个案选择拆行或拆表。图示承载表不强行变成三线统计表。

对大片空白或独占页按以下顺序定位：

1. 对象及题注能否在当前版心以可读尺寸容纳；先确认独占页是否合理。
2. 标题/正文/图题是否误设连续 `keepNext`；表题与首行、图片与图题是否配对。
3. 段前段后、固定行高、隐藏空段、手动分页或奇偶页分节是否共同挤页。
4. 表格列宽、数字/区间断行、重复表头和行拆分是否适合内容。
5. 必要时使用横向节、拆分长表或接受独占页；修改后重新核引用和页码。

不能把“每个图表页必须有正文”设为全文通用硬规则。它可以是某个短文稿的审美偏好；完整大型表、横向图或跨页表合理独占时应保留。自动工具标出位置和占用几何，作者通过最终 PDF 判断阅读连贯性。

## 9. 附录和 GitHub 电子补充材料

附录与正文独立清点、验收和编号。明确正文引用的卷、附录表/图号、版本及定位；独立 PDF 的页码不能冒充正文连续页码。必需的提交材料和解释应在实际提交包内，不能未经学校/用户确认用一个网页链接取代。

电子附录可公开通用代码、环境、合成示例及允许公开的材料。此次经验仓库只收通用策略与合成示例，真实论文附件、原始执行日志、账号绑定和机器路径不入公开仓库。受限数据说明来源和可重复调用接口。

推荐发布结构与检查例见 [电子附录发布](electronic-appendices.md)。正文用版本号、固定提交、文件名及 SHA256 标识电子材料；分开声明代码/文字/数据许可。Release/tag 是版本入口，不保证管理员不能修改；需要长期不变时结合不可变 Release 设置、归档存储或 DOI，并核下载字节。

## 10. 统稿和恢复的工程踩坑

| 失败现象 | 应查原因 | 修复与验收 |
|---|---|---|
| 合并后字段或题注顺序变了 | 样式同名异义、编号体系、书签/relationship 冲突、局部书目 | 合并前建映射；原生合并后核内容、字段、公式、图片和对象使用关系 |
| OOXML校验失败，但图形内容未改 | 布尔值序列化、settings子元素顺序或SVG根命名空间头不兼容 | 按实际schema和展开后的命名空间核查；保留数学设置及SVG几何/文字/属性，只改经核实的序列化问题 |
| 正确公式被报“内容改变” | Word 改了命名空间/运行格式/分页缓存 | 保留原始 XML 哈希，另比较带版本的语义结构；不得忽略 token、运算或数学属性差异 |
| 题注/表格又缩进两字 | 残余 `firstLineChars/hangingChars` 或样式继承 | 同时核字符与长度属性，保存重开后再验 |
| 宋体设置正确但 PDF 不对 | 主题字体、语言映射或字体替代 | 核实际字形字体和区域，而非只核字体清单里出现过宋体 |
| PDF写出却卡在关闭 | 只证明导出，不证明资源归还 | 保留已验PDF及 owned document，标cleanup pending；不重试、不关他人文档 |
| Word等待自己的锁 | adapter、Runner、PDF服务使用不同锁或重复获取同锁 | 统一持久锁；同线程可嵌套，其他线程/进程仍排斥，不删除锁 inode |
| NLM编号引用和答案论断对不上 | 目录命中、检索片段与最终引用错配、限定词遗漏 | 保留原答原引；同次返回的检索片段另列，经本地原文核对后裁决 |
| 旧界面显示“未完成”而磁盘已有终态 | 历史快照、投递未确认或重复恢复 | 先读最新磁盘清单、请求身份和终态，不按旧文本重发 |
| ZIP数量正确仍缺文件 | 同名覆盖、额外成员、旧文件、传输损坏 | 全成员集合、大小、CRC和SHA256逐件回读；审查回执与实物各自绑定 |

正常结束、文件存在、原生刷新、内容无变、结构通过、视觉通过、NLM返回、作者接受、封包与资源归还分别记账。任何一项不得代替其他项。已冻结的正文经验进入新工程任务，不为演示新检查器而再次修改或审读原论文。

## 11. 推荐交付

交付 DOCX、原生 PDF、可更新域核验、三目录目标页映射、图表/脚注/书目检查、已审范围和明确未决项。跨章 PPT、讲稿和音频绑定最终稿身份与页码；母稿尚未冻结时可起草，正式绑定时按影响范围更新。

OfficeCLI 负责排版和本地结构/渲染检查；论文精炼助手负责 NLM 审议、本地证据裁决和成果绑定。本工具不自动向 NLM 发请求，也不执行统计模型。检查器 `PASS` 仅表示契约覆盖的机械检查通过。
